Privacy policy

This policy explains what personal and operational information ZZveenus handles when you use the Discord bot, website, or dashboard.

Last updated: November 16, 2026

Who operates ZZveenus

ZZveenus is operated independently by its project operator. For privacy questions or requests, email zveenusdev@gmail.com or join the ZZveenus Support server and open a ticket in #make-ticket. A data protection officer has not been appointed.

Information the bot handles

To provide server features, the bot processes Discord server, channel, role, and member IDs, plus names or membership details when needed. Server configuration can include Steam alert channels, discount thresholds and filters; YouTube channel IDs, alert settings and seen video IDs; game-code alert settings and seen codes; announcement channels; moderation and vote-kick settings; sticky-role settings; AFK-kicker settings; blacklist status; and ZZveenus+ code references and expiry dates.

Economy and leveling are off until a server owner enables them. When enabled, server-specific files store member IDs with wallet and bank balances, cooldowns, XP, levels, and role reward, store, income, or boost settings. These balances are fictional in-server values and are not payment information.

When sticky roles are enabled, the bot stores member IDs, role IDs, and timestamps to restore roles after a rejoin. Records expire after 90 days. AFK kicker uses voice-state information and temporary in-memory timers to determine whether a human member is alone; it may disconnect that member and, after a later qualifying return, apply a 60-second timeout. AFK-kicker timers and disconnect strikes are held in memory and are not saved as member records; they reset when the bot restarts or the relevant cycle is cleared.

For a one-time new-server notice, the bot stores a joining server’s ID, name, join time, and notice-attempt state. It may send the operator a notice after about one hour and retains the attempt history to avoid duplicate notices; that history has no automatic expiry. ZZveenus+ redemption records contain code hashes and related server, redemption, and expiry details, rather than a reusable plain-text code.

YouTube channel-name and RSS validator caches contain channel IDs, display names, and feed validators such as ETags and Last-Modified values. These are operational cache data, not a message archive. Steam store metadata and background-checker health timestamps/status are kept in memory. Top.gg receives the bot’s server count and shard count; voting is not required to use commands.

Messages, commands, and lookups

The bot does not keep a general archive of server messages. Discord may deliver message content because the bot uses the Message Content intent. Leveling uses a qualifying message to calculate XP but does not save its text. Steam filter checks use deal titles and configured keywords. /filter test compares the sentence supplied for that command and does not save it as a record. The bot’s private owner commands process the owner’s command text in memory to perform the requested action.

If you use /steam-profile, the SteamID, vanity name, or profile URL you submit is used to request publicly available Steam profile details; ZZveenus does not keep a lookup history. YouTube creator names, handles, or URLs are resolved to channel IDs when a server configures creators, and those IDs are stored as server settings.

A server owner’s /request-deletion submission includes the selected data categories, optional notes, and the server and owner IDs. It is sent to a designated Support-server review channel and remains there until the operator removes the request message. Discord processes and stores that message under its own policies. The request is held for five minutes before it can be completed or declined; the owner can cancel it during that window or contact the operator.

Dashboard sign-in and website preferences

Dashboard sign-in uses Discord OAuth scopes identify and guilds. The dashboard receives your Discord user ID, username/display name, avatar, and server list/permissions so it can show servers and check access. OAuth access and refresh tokens, session IDs, CSRF state, and temporary rate-limit and server-list caches are held in server memory. The browser session cookie expires after eight hours. The matching server-side session expires after eight hours without activity or when the bot process restarts. The dashboard uses an HttpOnly session cookie; it does not use advertising or analytics cookies.

The website keeps your selected theme in your browser’s session storage for up to one hour; that preference is not sent to the server. Dashboard requests use the network peer address visible to the server for short-lived in-memory rate limiting and sign-in checks. Depending on the connection path, that address may be a proxy address. The server checks requests against an operator-maintained IP blocklist. Blocked-address and rejected-host events may log the peer address and supplied host headers to the bot console, with logging rate-limited. Hosting providers may keep their own access and security logs under their terms.

Regular dashboard settings are available only when you own the server or have Manage Server/Administrator permission and the bot is installed. The operator-only dashboard view provides basic server information, blacklist controls, and background-checker status. Its checker timestamps and generic status labels are held in memory, reset when the bot restarts, and do not include message content or service credentials. Blacklist changes are logged to the bot console with the operator ID and affected server name/ID.

Storage and service providers

Persistent bot data is stored on the bot host in per-server JSON files under data and data2, sticky-role files, subscription-code records, cache files, and global new-server notice state. The website is hosted through PebbleHost. A copy of these legal pages is hosted by GitHub Pages. These providers may process visitor or service connection data under their own policies.

Discord provides bot, identity, and server-list services and hosts deletion-request messages in the Support server. Top.gg receives aggregate bot server and shard counts. Steam and YouTube/Google provide public profile, sale, channel, and video information. Google also processes email sent to the operator’s Gmail contact address. Public feed providers supply game-code data. Requests are made when the related feature needs them. Each provider handles information under its own privacy policy and terms; processing may take place in countries where those providers or their infrastructure operate.

Retention and deletion

Server configuration, economy data, levels, role rewards, code-redemption records, and new-server notice history remain on the host while needed to operate the bot and do not all expire automatically. Sticky-role records expire after 90 days. The dashboard cookie expires after eight hours; its server-side session expires after eight hours without activity or when the bot process restarts. Temporary OAuth state expires after about ten minutes. YouTube display-name entries normally refresh after 24 hours. Temporary rate-limit data and AFK-kicker state are held in memory and expire or reset as the related process or timer ends.

A server owner can use /request-deletion to select saved data categories and add optional notes for a manual request; the command does not delete data itself. The submission is held for five minutes so the owner can cancel it using the button or contact the operator at zveenusdev@gmail.com or through Support. To complete removal, the operator must remove only the selected server data, which may include data/<server-id>.json, data2/<server-id>.json, data/stickyroles/<server-id>.json, a linked redeemed-code record, or that server’s new-server notice entries. Requests are handled manually. For access, correction, restriction, objection, or erasure requests about your personal data, email the operator or contact them through the support ticket and specify the data concerned. Some records may need to be retained where required by law or needed for a legal claim.

Your rights and complaints

Depending on applicable law and circumstances, you may ask to access or correct your data, request erasure or restriction, object to processing, or lodge a complaint with a supervisory authority. Where the GDPR applies, the information in this policy is intended to describe the controller, purposes, relevant recipients, retention approach, and ways to exercise rights. If you are in Estonia, you can contact the Estonian Data Protection Inspectorate. You can also contact the supervisory authority in your place of residence or work.

Security and changes

ZZveenus uses measures such as permission checks, rate limits, and restricted dashboard sessions to protect the service and its data. No online service can guarantee absolute security. This policy may change when the bot or dashboard changes; the date above identifies the latest revision.
